# 5주차 학습 기록

이번 5주차 과제 1차 PR 리뷰에서 멘토님께서 pytest 패키지를 활용해 테스팅을 진행하는 부분에 대해 말씀해주셨습니다.
사실 그동안 코드를 짜면 단순히 앱을 실행해보고 육안으로만 확인하고 넘어갔는데, 이번 기회에 AI에게 물어가며 본격적으로 파이썬 단위 테스트를 도입해 보았습니다. 그 과정에서 새롭게 배운 점들을 정리해 보았습니다.

## 1. pytest란?

테스팅 분야에 익숙하지 않다보니 처음에는 pytest 자체가 무엇인지에 대한 의문이 들었고, '테스트를 하면 기존 작성된 코드를 건드려야 하는 건가?' 하고 오해했습니다. 
하지만 AI와 대화하며 pytest는 메인 코드를 전혀 건드리지 않고, 별도의 파일에서 내가 짠 함수만 가져와 독립적으로 가짜 데이터를 넣고 검증하는 도구라는 것을 알게 되었습니다. 
이를 통해 기존 코드를 훼손하지 않으면서도 안정성을 보장할 수 있었습니다.

## 2. 테스팅 과정에서 들었던 의문점

이번 5주차 과제에서 헬퍼 함수인 `_collect_member_schedules`는 내부적으로 외부 데이터를 가져오기 위해 `call_mcp_tool_sync` 툴을 호출합니다. 
테스트 환경에서는 실제 MCP 서버가 켜져 있지 않을 텐데, 어떻게 외부 통신을 테스트해야 할지에 대한 의문이 들었습니다. 
이때 AI의 도움을 받아 `unittest.mock.patch`라는 파이썬 기능을 처음 사용해 보았습니다.

```python
with patch("student_parts.week05_load_kanas_past_conversations.call_mcp_tool_sync") as mock_call:
    mock_call.return_value = json.dumps(fake_external_response)
```
이렇게 작성하면 실제 네트워크 통신을 하지 않고도 함수를 가로채어 제가 직접 작성한 가짜 JSON 응답을 반환하도록 할 수 있었습니다. 
덕분에 외부 환경에 의존하지 않는 순수한 함수 자체의 로직만 테스트할 수 있었습니다.

## 3. 검증 목록

이번 과제에서 고민하며 구현했던 여러 조건 처리들을 테스트 코드를 통해 전반적으로 검증해 보았습니다. 우선 멘토님의 피드백을 반영하여 추가한 `ok`, `tool_name` 같은 메타데이터가 반환 딕셔너리에 올바르게 포함되어 있는지 확인했습니다. 
또한 입력한 날짜 범위를 벗어난 내 개인 일정이 결과 리스트에서 정상적으로 걸러지는지를 테스트했으며, 특히 시간 데이터가 없는 일정을 병합할 때 "미정"이라는 문자열 대신 `None` 값이 그대로 잘 유지되는지도 테스팅을 통해 검증했습니다.

## 4. 마무리

지금까지는 화면이나 터미널에 찍히는 로그를 직접 눈으로 확인하는 것에 그쳤지만 이렇게 코드로 명확하게 조건을 걸어 검증하고 테스트가 성공적으로 passed 라는 것을 확인하니 제가 작성한 코드에 대해 정상적으로 동작한다는 확신을 얻을 수 있었습니다. 
앞으로 기능 추가나 리팩토링을 할 때, 테스트 코드 작성을 꾸준히 시도해 보려 합니다. 
이번 주차에서는 테스트 코드를 작성할 때 AI의 도움을 많이 받았는데, 앞으로는 테스팅에 대한 이해도를 높여 직접 작성하는 데에 도전해 보려 합니다.
