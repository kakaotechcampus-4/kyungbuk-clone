# 6주차 학습 기록

이번 6주차 과제를 진행하며 AI에게 질문했던 것들이나 AI의 답변으로부터 얻은 것들을 간단하게 아래와 같이 정리해보겠습니다.

## 1. 프롬프트는 곧 코드이자 계약서이다

이전까지는 프롬프트를 단순히 LLM에게 보내는 대화형 지시문이라고만 생각했습니다. 하지만 이번 주차에 각 에이전트의 역할을 나타내는 프롬프트(nana_prompt_parts, kana_prompt_parts)와 툴 설명서 프롬프트(FIND_COMMON_AVAILABLE_SLOTS_DESCRIPTION, DECIDE_FINAL_SLOT_DESCRIPTION)를 작성하면서 프롬프트에 대해 AI에게 리뷰를 받았습니다.
리뷰 응답 중 AI가 "프롬프트는 단순한 텍스트가 아니라 모델의 행동을 통제하는 엄격한 API 계약서와 같다"라는 응답을 해주었고, 이를 통해 프롬프트 설계의 중요성을 배울 수 있었고, 그 결과로 프롬프트를 작성하는데 어떻게 프롬프트를 더 발전시키면 더 나은 결과를 얻을 수 있을지 생각하며 작성해볼 수 있었습니다.

## 2. 파이썬 로직과 툴 래퍼(@tool)의 완벽한 분리

그룹 일정을 조율하는 과정에서 'find_common_available_slots' 도구를 구현할 때, 처음에는 파이썬의 비즈니스 로직과 '@tool' 래퍼의 역할을 혼동하여 래퍼 안에서 모든 것을 처리하려다 로직이 꼬이는 경험을 했습니다.
AI와의 대화를 통해 실제 데이터 정규화나 누락된 데이터를 조회하는 복잡한 처리는 내부의 헬퍼 함수로 완전히 위임해야 한다는 설계 패턴을 배웠습니다. 이를 통해 코드의 가독성이 높아지고, 향후 단위 테스트를 작성하기도 훨씬 수월해질 것이라는 것 또한 깨달을 수 있었습니다.

## 3. 코드의 안정성을 높이는 사항

헬퍼 함수로 데이터를 넘길 때 인자가 많아지다 보니, 순서가 헷갈려 치명적인 버그가 발생할 수 있다는 점을 알게 되었습니다. 이를 방지하기 위해 key=value 형태의 키워드 인자를 적극적으로 사용하여 파이썬 코드의 안정성과 가독성을 높이는 방법을 체화했습니다.

## 4. 마무리

이번 주차 과제 내용 중 프롬프트 작성 부분이 큰 비중을 차지했던 만큼, 프롬프트 작성에 많은 시간을 들였던 것 같은데 이번 과제를 통해 직접 프롬프트를 작성하고, AI에게 리뷰를 받으며 좀 더 나은 프롬프트를 작성하는 방법에 대해 깊이 고민해본 것 같아 좋았습니다.
